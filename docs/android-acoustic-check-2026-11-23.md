# Проверка сомнительных фраз на Android

Сравнение с `cd879d2`. Приложение оценивает уверенность в речевых токенах отдельно от пунктуации. Слабое слово даёт всей фразе отметку проверки.

## Что подтвердилось

На дожде сеть даёт `а` во втором CTC-кадре: оценка 0,255 против 0,247 у blank. На пылесосе она даёт `Д` в первом кадре и `а` на 0,52 с. В обоих случаях 122 из 125 кадров выбирают blank. **Beam и greedy дают те же лишние слова**. Ошибка уже содержится в акустических выходах сети; замена одного CTC-декодера другим эти два случая не устраняет.

Отдельная точка в конце файла имеет высокую оценку. У шумового `а.` прежняя средняя оценка слова — 0,605, буквенной части — 0,255. У `Да.` на пылесосе — 0,625 и 0,525. Эта средняя не является калиброванной вероятностью правильности слова.

Проба `CPci7a8l-oU_0101-не-isolated` вырезана из фразы «И не болейте» с границами 0,18–0,38 с. В полном контексте CTC ставит `не` на 0,28–0,32 с, а начало `бо` следующего слова — на 0,36 с. Конец среза пересекается с соседним словом **по этой модельной разметке**. Это не чистый однословный золотой эталон.

Те же 0,20 с PCM без пауз дают `Не`, посередине пятисекундной дорожки — `Небо.`. В последнем случае сеть выносит `Н` на 0,04 с цифровой тишины, `е` — на 2,44 с, `бо` — на 2,60 с. Звук в PCM находится только на 2,40–2,60 с. После удаления последних 20 мс среза вариант в середине паузы даёт `Не.`. При других паузах ответы снова различаются. Подтверждены чувствительность к границе и контексту паузы; универсальное обрезание речи из этого не следует. Ручной фонемной разметки нет.

## Отвергнутые правила

Все правила проверялись в сгенерированной копии Java, без записи в приложение. Порогам не передавались имена файлов и списки запрещённых слов.

| Опыт на 24 прежних шумах + 52 коротких случаях | Слова на шуме | Замены / пропуски / вставки в речи |
| --- | ---: | ---: |
| База | 2 | 27 / 7 / 13 |
| Удалить одиночный beam-ответ, когда greedy не даёт букв | 2 | 27 / 7 / 13 |
| Проверить ранний одиночный ответ <0,8 с добавлением 640 мс нулей | 0 | 24 / 10 / 12 |

Второе правило проверяет наличие распознанного начала после добавленной паузы. Оно убрало оба шумовых ответа, но сделало пустыми **три WAV с голосом**:

- `CPci7a8l-oU_0101-не-end-5s`: `Н.` → пусто;
- `cPhc8OVB2Rk_0126-не-start-5s`: `Что-нибь?` → пусто;
- `7hkxVyhoMoQ_0040-да-end-5s`: `А.` → пусто.

До опыта эти ответы уже были неверны. Правило не удалило три правильно записанных слова: оно превратило неверный непустой ответ в пустой. Общий WER речи даже уменьшился с 47 до 46 ошибок, но число пропусков выросло 7 → 10. Для задачи сохранения тихой речи такого выигрыша недостаточно; правило в приложение не перенесено. На отдельном наборе из 37 коротких проб текст не изменился, что не отменяет найденных контрпримеров с голосом.

Проверок с начальной паузой стало 5 → 12. Внутри этих инструментированных проходов JVM суммарное время выросло с 3,178 до 7,815 с. Это **семь дополнительных распознаваний**, около 4,64 с измеренной работы стенда. Скорость телефона не измерена, общую разницу времён нельзя приписать только правилу.

## Правка, оставленная в приложении

`PhoneGigaAm` сохраняет отдельный `speech_conf`: среднюю оценку токенов с буквами или цифрами. Отдельная пунктуация её не повышает. Прежний `conf` сохранён для выбора прохода, сверки вариантов и всех условий повторной обработки.

`PhonePhrases` дополнительно помечает фразу, если речевая оценка слова ниже **существующего порога 0,55**. Старые причины сомнений сохранены через OR. Текст, таймкоды, группировка и расчёт старой средней уверенности не изменены. Новых акустических проходов нет. Смешанный токен с буквами и пунктуацией считается целиком; это диагностическая оценка токенов, а не независимая оценка смысла слова.

| Проверка | Ошибки до → после | Новые отметки на ошибочных / правильных фразах |
| --- | ---: | ---: |
| 99 прежних WAV, 1110 слов | 171 → 171 | 3 / 0 |
| 9 новых целых контекстов, 120 слов | 18 → 18 | 0 / 0 |
| 37 отдельных коротких проб, 53 слова | 12 → 12 | 0 / 0 |
| 16 новых шумов ESC-50 | 1 → 1 лишнее слово | 0 / 0 |
| 24 прежних шума | 2 → 2 лишних слова | 0 / 0 |

На 99 WAV отмеченные фразы выросли 22 → 25. По корпусным эталонам новые три отметки охватили **11 ранее не отмеченных словесных ошибок**, включая вставленное `ну` и пропуски в двух фрагментах mTEDx. Правка эти ошибки не исправляет. Дополнительных отметок на правильных фразах в проверенных наборах не появилось. Оценка ошибок выполнена фиксированным выравниванием с субтитрами, без ручного прослушивания каждого слова; это ограниченный контроль, не общая калибровка флага.

**Реально видимый `needs_review` сменился у трёх фраз: false → true; все три ошибочны по эталону. True → false нет. Дождь и пылесос уже имели `needs_review=true` до правки и сохранили его.** Видимое улучшение относится к трём речевым фразам; шумовые слова этим исправлением не удалены.

На всех пяти наборах сохранены прежние флаги, текст, времена и число проходов моделей. Числа и отрицания не изменились. Два прежних ложных слова на шуме и один ответ на новом шуме остаются нерешёнными.

## Данные и повторение

Настройка фильтров — прежние 24 шума и 52 коротких случая. Отдельная проверка содержит 99 прежних WAV, 9 новых полных фрагментов mTEDx и 16 новых записей [ESC-50](https://github.com/karolpiczak/ESC-50) из fold 1/2. У шумов исключены прежние исходные Freesound ID; правило выбора записано до ASR. Девять новых фрагментов выбраны по эталонам, без вырезания целевого слова. Выступления могут повторяться.

Ещё 37 проб — 23 отдельные контрольные записи основного чата и 14 копий семи целых однословных записей: добавлена тишина справа до 5 с, для половины копий gain 1/16. Новых границ внутри слова нет. Набор не пересекается по исходным ID с настройкой фильтров; производные копии не являются независимыми говорящими. Пересборка всех 37 WAV дала те же SHA побайтно. Новые шумовые ответы требуют прослушивания: пустой эталон задан по условию набора, а не ручной разметке фоновых голосов.

Все замеры здесь — **Android Java / ONNX Runtime JNI в JVM на Mac**. Параллельная нагрузка менялась, обычный стенд для части базовых запусков делал два повтора. Сопоставлялись первые повторы и реальные счётчики вызовов; процент ускорения не заявляется.

Артефакты: `work/acoustic/audit-final.json`, `confidence-frozen.json`, `tune-*.json`, `control-{normal,observe,confidence}.json`, `independent-{base,prefix,confidence}.json`, `boundary-observe.json`. В каждом диагностическом проходе сохранены события токенов, их оценки, blank, greedy и наличие ненулевого PCM поблизости. Диагностический режим проверен сравнением с обычным стендом: ответы и метки совпали. [Метрики, примеры, планы, входы и SHA](android-acoustic-check-2026-11-23.json).

```sh
python work/test_android_acoustic_evidence.py
python tools/probe_android_acoustics.py work/acoustic/tune.json \
  --source-root work/acoustic/base --policy onset-single \
  --deps "$ASR_JVM_DEPS" --jdk "$JAVA_HOME" \
  --model work/models/gigaam/v3_e2e_ctc.int8.onnx \
  --output work/acoustic/prefix-repeat.json --repeats 1
```

`tools/prepare_android_acoustic_checks.py` пересобирает голоса, шумы, паузы и независимые короткие пробы. Старый Android-код сохранён в `work/acoustic/base`; текущая правка сверена с проверенной копией `confidence-candidate`. Прошли 22 теста, из них три новых — на речевую оценку, сохранение старого флага и работу при отсутствии нового поля в JSON.

На JVM остались ложные слова на шуме и ошибка «небо» на вырезанном «не». Для оценки в аудитории нужна запись с ручной разметкой слов и таймкодов.
