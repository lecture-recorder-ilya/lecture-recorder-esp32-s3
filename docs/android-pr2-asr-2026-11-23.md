# Android ASR: main/0.5.10 и PR № 2

На одних русских PCM обе версии дали одинаковые тексты всех 225 речевых случаев: **284 ошибки / 1529 слов, WER 18,57%**. На 42 неречевых случаях main дал **9** лишних слов, PR — **17**. Наши защиты шума и таймкодов сохраняются. Из PR перенесён предсказуемый выбор штатной модели: отдельный коммит `9187bc41730993ed00cdbecca83a1cb247a37a07`. Параллельность не менялась.

- Срез `origin/main`: **`186b41e1dd59f97b6c7f05ae46daadd62a662b50`**. Его Android-код совпадал с тегом `v0.5.10`, commit **`f59125ca635b1eb88e6532e38e25f31262c240d4`**.
- Во время работы main продвинулся до `ade8527158912a721e6d2ce7bca29fe3a587fff6`; шесть измеряемых ASR-классов, frontend и токены по сравнению со срезом не изменились.

- Состав до запуска: все 139 reproduced + 92 control + 24 independent + 12 quiet-holdout, **267 WAV**. Составной manifest SHA256 **`662f31cac6c562a8be2edcd29a27267bb6595416f499d681524b7701d7d91e04`**. Источники прежние, заново по результатам не отбирались.

Использованы только открытые Golos/OpenSTT/mTEDx/ESC-50 и ранее подготовленные контрольные преобразования. Личных записей, сообщений и личных весов не использовали, аудио наружу не отправляли. Control включает модель комнаты, short — также вырезки и искусственные паузы. Это не новые полевые записи и не оценка независимых говорящих. Поле synthetic из старой разметки не определяет происхождение сценария: для этого использованы исходные subset и правила подготовки. В архивном составном манифесте отсутствие такой метки было записано false; этот манифест сохранён неизменным. При новой подготовке скрипт оставляет отсутствие метки как null. Состав, PCM, эталоны и метрики от этой технической аннотации не зависят.

## Условия прогона

Настоящие Java-классы Android скопированы в отдельный JVM-стенд без изменения их кода. Сверены SHA скопированных исходников. Android Context/Store/Job заменены файловыми заглушками; UI, Vosk fallback, системное планирование Android и физический телефон здесь не проверялись.

Mac Apple M2, 16 GiB RAM, 8 логических CPU, macOS 27.2.1; OpenJDK 21.0.13, ONNX Runtime JNI 1.24.3. В рабочих SessionOptions четыре intra-op потока, один inter-op, GPU-провайдеры не подключаются, используется стандартный CPU-путь ORT. Поле providers в сырых JSON получено через getAvailableProviders и перечисляет **доступные** CPU/CoreML/WebGPU, а не выбранные для инференса. Это замер Android Java на настольной JVM, не скорость телефона.

## WAV и таймкоды

Для сравнения декодирования изменён только WAV-заголовок; PCM каждого из 267 входов сохранён побайтово и снабжён отдельным SHA. Обе версии получили одинаковые новые WAV. Причина: отдельный parser-only прогон исходных файлов показал **0 отказов main и 59 PR** на WAVE_FORMAT_EXTENSIBLE PCM. Это отказ PcmWave в прямом пути GigaAM; работоспособность всего приложения через Vosk fallback из этого не выводится.

Дополнительный разбор сохранённых результатов, без повторного ASR: 32 непустых речевых случая с не менее 0,5 с точной цифровой тишины у края PCM. Конец фразы ушёл более чем на 0,5 с за последний ненулевой отсчёт в **0 случаях main против 24 PR**; максимум PR — **4,82 с**, main — 0,40 с. Слишком раннее начало по тому же критерию осталось у **9 main против 24 PR**. Это узкая физическая граница на данном контроле, не полная ручная разметка границ слов. Порог 0,5 с использован только в отчёте, код распознавания не настраивался.

## Подтверждённые различия кода

[PhoneGigaAm на зафиксированном head PR](https://github.com/lecture-recorder-ilya/lecture-recorder-esp32-s3/blob/f5d87339ba6f5bfd42edd58d5318150d041a888c/outputs/android/src/ru/ilya/lecturerecorder/PhoneGigaAm.java) — проверенная реализация, без вывода о её происхождении. PR выбирает два worker для записи от 90 с при availableProcessors >= 6, иначе один; выдаёт завершённые окна по порядку и передаёт callback в PhonePhrases. Main использует один worker, проверку сомнительного начала одиночного слова, речевые токены для времени, PhoneWordTimeline для стыка и trimSilentStart для доказанной нулевой паузы. Условия PhonePhrases main также учитывают speech_conf. Промпт GPT, авторство идеи и внешние первоисточники здесь не исследовались; этим занимается отдельный чат.

## Выбор весов: отдельное исправление

По [b3f42a6](https://github.com/lecture-recorder-ilya/lecture-recorder-esp32-s3/commit/b3f42a6aeedc6dd4b7258237dbf23ce73389a2bd) перенесён выбор штатной модели. В срезе main наличие любого файла gigaam-personal.int8.onnx делало акустику готовой и давало ему приоритет. Исполняемый тест на настоящем PhoneModels подтвердил это даже на трёхбайтовой фикстуре; в PR при наличии штатного файла выбирается штатный. После исправления наш выбор совпадает с PR, наличие только личного файла не означает готовность, сам личный файл сохраняется. Если штатной модели нет, требуется её обычная загрузка.

Это изменение маршрута выбора, не измеренный выигрыш WER личных весов. Ни одной личной модели не загружали и не оценивали; качество или скорость таких весов неизвестны. Сравнение алгоритмов выше принудительно использует одну штатную модель и не смешивается с этим эффектом. Vosk fallback и сохранённые ранее конспекты не менялись.

38 unittest и отдельная Java-программа проверки состояния расшифровки прошли без пропусков, включая пять новых тестов выбора модели, CTC alignment, PCM/WAVE, таймкоды, числа/отрицания, акустические флаги и одиночные проходы. Пропущенный сначала test_android_asr_passes повторно пройден с заданным CLIPMIC_ASR_DEPS; первоначальный лог сохранён. После измерений в заглушку Job добавлен publishPhrase(JSONObject), делегирующий в тот же preview.addPhrase. Отдельный компилируемый Java-тест подтверждает оба варианта method reference и единый счётчик; распознавание ради этой совместимости не повторялось. Новых комментариев в код не добавлено.

## Артефакты и воспроизведение

Каталог `work/android-pr2-asr/` в общей рабочей области. `fixture/manifest.json`, `long-manifest.json`, `lock.json` — входы и фиксация до моделей. `results/ours.json`, `ilya.json`, `ours-long.json`, `ilya-long.json` — все результаты; `comparison.json` — сводка и SHA. `timing-bounds.json` — физические границы; `*-native.json` — проверка заголовков; `model-selection-before.json` и `model-selection-tests.log` — выбор весов; `regression.json` — тесты. В environment.json сохранены только технические параметры, SHA и версии. В docs/android-pr2-asr-2026-11-23.json — копия итоговой сводки.

Стенд `tools/compare_android_asr.py` использует общие scorer и исходный Android-код. В подготовке не вызываются модели. Повтор в новых выходных файлах:

```sh
python tools/compare_android_asr.py prepare REPO NEW_FIXTURE
python tools/compare_android_asr.py run NEW_FIXTURE/manifest.json --source WORKTREE --deps DEPS --jdk JDK --model STOCK_ONNX --output NEW_RESULT.json
python tools/compare_android_asr.py run NEW_FIXTURE/long-manifest.json --source WORKTREE --deps DEPS --jdk JDK --model STOCK_ONNX --repeats 3 --output NEW_LONG_RESULT.json
```

python — локальный work/asr-env/bin/python; DEPS — work/lecture-profile-local-asr/asr-check; JDK — work/publish-0.5.5/toolchain/jdk-21.0.13.1+2/Contents/Home. Для parser-only добавить --native. Готовые результаты не перезаписываются. Приложение не публиковалось, общие версии и main не менялись.
