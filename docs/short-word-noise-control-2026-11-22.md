# Короткие слова при отсечении шума Android

Архивный замер от 22 ноября 2026 года. В таблицах указаны ревизии, на которых его выполняли. Для версии 0.5.10 нужен отдельный прогон.

**Риск потери настоящего слова подтверждён.** В вырезке «не» из живой речи `CPci7a8l-oU_0101` Android даёт `Не` с уверенностью **0,453**. В её тихой копии с паузами — `Не.` с уверенностью **0,639**. Шумовые `Д.` на ESC-50 имеют уверенность 0,433 / 0,488 / 0,672. Порог 0,70 удаляет все три шумовых ответа и обе эти сохранённые версии настоящего отрицания. Это два варианта одного источника, не два независимых говорящих.

У `Три.` и `Да.` после добавления тишины слово имеет таймкод на весь пятисекундный файл, хотя вырезка голоса длится 0,18–0,28 с. Уверенность при этом выше 0,99. Поэтому длина одиночного слова по текущим таймкодам также не отделяет речь от трёх шумовых `Д.` с длительностью 5 с.

## Зафиксированный контроль

Выбор сделан до Android-распознавания и просмотра нового фильтра. Из локального `ru-test.parquet` mTEDx выбраны по четыре кратчайших эталона со словами «не», «три», «да», по одному на выступление для каждого слова. Проверенные ранее ID исключены по манифестам. Это 12 новых сегментов семи выступлений; часть самих выступлений уже встречалась в прежних опытах.

Сохранены все 12 исходных контекстов. В восьми удалось получить временные границы целевого слова из CTC/RNN-T Mac. Из них созданы пять вариантов: короткая вырезка, середина 5 с тишины, тихая середина (gain 1/16), начало и конец 5 с. Всего **52 речевых WAV**. Ещё четыре случая остались полными контекстами, без подбора более удачных замен. Один из исходных контекстов содержит песенный фрагмент. Для сравнения повторно использованы восемь предоставленных ESC-50, без объявления их новым шумовым контролем.

Вырезки содержат реальный голос, TTS не использован. Границы автоматические, с запасом 60 мс: в некоторых срезах возможны части соседних звуков. Это проверка риска фильтрации на живом материале; для строгого эталона отдельно произнесённых слов нужна ручная фонемная разметка или самостоятельные записи ответов. Основные контексты сохранены для прослушивания.

| Целевое слово | Сохранено в полных контекстах | Сохранено в вырезках и вариантах |
| --- | ---: | ---: |
| не | 3 / 4 | 5 / 15 |
| три | 3 / 4 | 13 / 15 |
| да | 3 / 4 | 5 / 10 |

Это присутствие целевого слова, а не доля полностью верных расшифровок. Для «три» допускается цифровая запись `3`. На 12 неизменённых контекстах базовый Android имеет 21 ошибку на 83 слова; эти исходные ошибки сохранены в отчёте. Короткие срезы не объявляются безошибочными эталонами всех окружающих фонем.

Два реальных прогона JVM на Mac M2: 60 WAV с шумом, 240,06 с входа; время вызовов 39,821 и 39,768 с. Тексты, флаги и таймкоды двух прогонов совпали. Все восемь шумовых ответов также точно совпали с предоставленным `android-noise-after.json`: три `Д.`, остальные пустые. Скорость телефона не измерена.

## Диагностика простых отсечений

До чтения ответов Android зафиксированы три исследовательских правила. Они воспроизведены на сохранённых списках слов; в приложение их не добавлял. Дополнительные потери считаются только относительно уже сохранённого базой целевого слова. Исходная ошибка базы не считается новой регрессией.

| Отсечение одиночного слова | Слова на ESC-50 | Дополнительно потеряно «не» | «три» | «да» |
| --- | ---: | ---: | ---: | ---: |
| Без отсечения | 3 | 0 | 0 | 0 |
| Любое одиночное слово | 0 | 2 | 10 | 5 |
| Уверенность <0,70 | 0 | 2 | 0 | 0 |
| Длительность слова >1 с | 0 | 1 | 8 | 4 |

Числа здесь относятся к вариантам WAV. Удаление всех одиночных слов теряет 17 сохранённых ответов из четырёх исходных слов. Удаление длинного одиночного слова теряет 13 вариантов тех же четырёх источников. Снижение ложного текста на восьми шумах само по себе такой фильтр не обосновывает.

**Новый Android-фильтр владельца в этой проверке ещё не оценён.** Граница проверки: прогнать его на замороженном манифесте, сравнить те же PCM и отдельно показать добавленные потери относительно базы. Пять тестов выбора, подсчёта и защиты входа прошли. Код приложения и общее дерево не менялись.

## Артефакты и повторение

Каталог `work/short-word-control/`: `sources/sources-plan.json` — выбор до ASR; `sources/manifest.json` — полный живой контекст; `frozen/manifest.json` — 52 речевых случая; `comparison-manifest.json` — они же плюс восемь шумов; `android-baseline.json` — два прохода с первичными словами и уверенностью; `audit-v2.json` — разбор потерь; `acceptance.json` и `diagnostic-plan.json` — критерии до проверки. [Числа, все входы, примеры и SHA](short-word-noise-control-2026-11-22.json).

```sh
repo="$(git rev-parse --show-toplevel)"
python3 work/test_short_word_control.py
# source-root — отдельная копия проверяемого Android-фильтра
python3 tools/profile_android_asr.py \
  work/short-word-control/comparison-manifest.json --source-root "$candidate" \
  --deps "${CLIPMIC_ASR_DEPS:?укажи каталог с ort.jar и android-json.jar}" \
  --jdk "${JAVA_HOME:?нужна JDK 17}" \
  --model "$repo/work/models/gigaam/v3_e2e_ctc.int8.onnx" \
  --output work/short-word-control/android-candidate.json --repeats 2
python3 tools/audit_short_word_control.py \
  work/short-word-control/android-baseline.json work/short-word-control/comparison-manifest.json \
  --plan work/short-word-control/diagnostic-plan.json \
  --candidate work/short-word-control/android-candidate.json \
  --output work/short-word-control/candidate-audit.json
```

Для пересборки входов использован `tools/prepare_short_word_control.py sources`, затем `crops`. Для чтения источников нужен Python с pyarrow. Все пути исключающих манифестов и SHA parquet записаны в `sources-plan.json`, SHA разметки — в `frozen/frozen.json`. Артефакты не перезаписываются: повтор требует нового выходного каталога.

**Физическая проверка:** реальные отдельно сказанные короткие ответы нескольких людей на телефоне и их ручная разметка. Новый фильтр следует проверять также на целом контексте: запрет удаления одних только «не» и чисел не защищает «да», «я», «и» и остальные короткие слова.
