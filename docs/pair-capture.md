# Парная запись для проверки ASR

Формат сверён с протоколом чата «ClipMic · Корпус, крепление и материалы» в ветке RV/next-p1-bench. Короткая серия использует 27-секундный стенд P1 и его JSON из `bench/compare.py`. Для длинной серии в корпусном чате отдельно заданы шесть речевых блоков и семь меток. [Короткий стенд](../hardware/clipmic-p1/bench/README.md) · [Длинная серия](../hardware/clipmic-p1/bench/LONG.md)

1. Одна и та же колонка и фонограмма с зафиксированным SHA-256 на 1, 3 и 5 м. Уровень выставить на 1 м и затем сохранить. Записать фактическую дистанцию от центра передней плоскости динамика до каждого входа, высоту, азимут, ориентацию и сторону. Входы рядом в одной плоскости, по возможности не дальше 5 см друг от друга. Те же корпус, крепление и обработка телефона. Четыре одновременных дубля на дистанцию с порядком сторон Л–П–П–Л.
2. Два устройства пишут один дубль. Начать запись до воспроизведения, сохранить исходники и журнал P1. В отчёте короткого стенда две метки в мастер-файле на 1 и 25 с, в каждой дорожке остаются их собственные таймкоды. `compare.py` отклоняет слабые или повторные метки и расхождение интервала больше 0,5%. Отклонённый дубль хранить отдельно, в таблицу распознавания брать пригодные.
3. Для комнаты записать размеры или описание, число присутствующих, фон и работающую вентиляцию, высоту и неизменную громкость колонки. Для ClipMic указать ревизию PDM-платы и конфигурацию корпуса. Для телефона указать модель, приложение, активный микрофон или предполагаемый вход, канал, положение, AGC и исходный кодек. Имя пары одинаково для двух дорожек, SHA-256 фиксируется отдельно для каждого оригинала и для WAV распознавания.
4. Один текст привязать к мастер-фонограмме всей серии. В коротком стенде это `scripted` — исходный сценарий синтетической речи из корпусного протокола. Для живого мастера после отдельного прослушивания использовать `manual_verified`, указать `reviewer` и `checked_at`, сохраняя дословные числа, отрицания, повторы и оговорки. Синхрометки и фон из оценки текста исключить. Разметка одна на обе дорожки, реальное прослушивание и сравнение уровня проходят отдельно.

## Минимальный локальный паспорт

```json
{
  "room": "описание комнаты и фона",
  "source": "колонка, высота, уровень",
  "reference": {"wav": "reference.wav", "sha256": "...", "reference_type": "scripted", "text": "..."},
  "takes": [
    {
      "id": "сессия-1m-L-01",
      "distance_m": 1,
      "sync_json": "1m-L-01.json",
      "ClipMic": {"wav": "p1.wav", "original": "p1.wav", "original_sha256": "...", "channel": 1, "device": "P1, ревизия", "microphone": "PDM, активный вход", "position": "Л, азимут, корпус", "distance_measured_m": null, "height_m": null},
      "phone": {"wav": "phone.wav", "original": "phone.m4a", "original_sha256": "...", "channel": 1, "device": "модель и приложение", "microphone": "вход, обработка", "position": "П, азимут", "distance_measured_m": null, "height_m": null}
    }
  ]
}
```

Добавить пары на 3 и 5 м и повторы. Все поля с фактическими измерениями заполняются после съёмки. Из QA-копии проверить файлы командой `python3 tools/check_pair_capture.py /путь/к/серии/series.json`. Шаблон не содержит полевых данных. Физическая проверка P1, комнаты, микрофонов и участия людей остаётся открытой.

## Проверка формата

Синтетическая дорожка стенда сдвинута на 125 мс и подана как дорожка телефона. Штатный `compare.py` нашёл метки ClipMic на 1,000 и 25,000 с, телефона на 1,125 и 25,125 с. Валидатор принял три синтетические пары и отклонил подменённый SHA-256 оригинала. Локальный протокол — `work/long-asr/pair-smoke/check.log`. Проверка охватывает обработку файлов и синхронизацию.
