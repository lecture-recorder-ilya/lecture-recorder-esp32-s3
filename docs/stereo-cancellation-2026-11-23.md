# Сохранил речь при противофазе стереоканалов

База: `a3f839182d9d2feb19c83ee67615276027f3ab95`. Изолированная ветка `RV/release-0510-asr`. Версия приложения, v15, пороги, модели, Android и общие отчёты 23 ноября не менялись.

## Исправление

При импорте WAV с двумя точно противоположными каналами прежний downmix складывал их в цифровую тишину. Реальный PCM `golos-1571`: 99 805 отсчётов, 98 817 ненулевых; в таком стереофайле после прежнего normalize — 0 ненулевых отсчётов. Это потеря звука до распознавания.

В `audio_import.normalize` добавлена узкая проверка: PCM16 stereo 16 кГц, **каждая** пара отсчётов во **всём** файле в сумме даёт ноль, хотя бы один отсчёт ненулевой. В этом случае сохраняется левый канал с исходными значениями. Проверка потоковая, блоками по 30 секунд; обрыв WAV отвергается. Моно возвращается прежним быстрым путём. Любое отличие, включая один отсчёт в конце, оставляет прежний downmix. Нет VAD, новых моделей, усиления, порога корреляции или выбора «голоса преподавателя».

## A/B на одних WAV

Состав зафиксирован до A/B, manifest SHA256 `4e034a66f4abcd00f2aafdfdd5aca11174046b83b9b283ca96b93d210ef48886`. Четыре заранее выбранных фрагмента Golos/OpenSTT/mTEDx, их моно/противофазные копии, два обычных стереоконтроля, все 40 шумовых входов reproduced139 в противофазе и цифровая стереотишина: **51 WAV**. Это смоделированные каналы реальных открытых записей; не независимый полевой контроль и не реальные два микрофона. При наличии -32768 оба канала шумовой фикстуры заранее масштабируются вдвое, чтобы точное отрицание помещалось в PCM16. Состав не отбирался по ответам ASR.

Улучшились четыре текста, ухудшений нет. Стало на 49 словных ошибок меньше; оставшиеся четыре строгие ошибки равны ошибкам на исходном моно. Деньги «девять тысяч рублей» переданы как «9 000 рублей»; строгий scorer не приравнивает цифровую запись словам. Нормализованный WAV, полный текст, слова, таймкоды и needs_review каждого восстановленного примера совпали с его исходным моно. Отдельно импортированы все **92** контрольных моно-WAV обеими версиями: хеши совпали 92/92.

Основной A/B — `GigaAM-v3-3pass-phrases-v15-quiet-char-int8`; результат дополнительно повторился без необязательного character-int8. До/после использованы одинаковые веса; SHA256 character-int8 `ceb61454e2e1a2dec5872cbac1de0fe0a4271d1148f6b26b5bda53ff30a12acd`. Остальные 56 Python-модулей recorder побайтово равны базе.

Mac CPU, один запуск на сторону, без изоляции нагрузки. Инференс на четырёх обычных моно (23,574 с аудио): 5,888 → 5,709 с; это не доказательство ускорения. Полный инференс 51 входа: 6,487 → 9,158 с, потому что восстановленная речь теперь распознаётся (2,208 с на четыре противофазных фрагмента), а сохранённый шум проходит VAD. Новых ASR-проходов над прежним моно не добавлено. Скорость Android/телефона не измерялась.

## Проверки

- Шесть новых тестов: точная противофаза, сохранность моно/оригинала, отличие на один отсчёт после границы 30 с, тишина/обычное стерео/минимум int16, потоковая запись и усечённый WAV.
- Полная прежняя регрессия + новые тесты: 275 обнаружено, **274 успешно**, 1 пропущен (`test_recorder_verification_does_not_wait_for_installer_lock`: в worktree нет bundled Python установщика).
- С доступным character-int8: **175 ASR-тестов успешно**, без пропусков. Android alignment запускался с JDK из локального toolchain.
- Старый `test_brief_speech` зависел от наличия файла int8 и падал с `KeyError: char_fast` также на чистой базе. Его фикстура теперь явно выбирает полный подставной character-декодер; продуктовая политика fast/precision не менялась.
- `git diff --check` без замечаний. Все 51 хеш входа совпали между сторонами; исходные WAV не менялись.

Формы терминов и защита отрицаний из `69730d0` уже есть в базе, шесть тестов term hints проходят. Android-оптимизации `shouldRefine` и проверки constant на обрезанном окне также уже сохранены. Старый стереоадаптер выбора канала по VAD оставался экспериментом: целиком он не переносился. Повтор коротких сомнительных участков отдельно испробован на трёх уже отмеченных пропусках control92: CTC/RNN-T не подтвердили общий ответ; лишние проходы в продукт не добавлены.

## Артефакты и повтор

Каталог в общей рабочей области: `work/release-0510-asr/`. В `fixture/manifest.json` исходные стереовходы и эталоны, `fixture/lock.json` — правило/хеши. В `results/comparison.json` — сводка, изменённые тексты и SHA доказательств; `stereo-fast-before.json` / `stereo-fast-after.json` — полные результаты. `mono92.json`, `regression.json`, `fast-core-regression.json` содержат отдельные проверки. Первые пробы и неудачный запуск тестов сохранены отдельно, итоговые результаты их не скрывают.

Подготовка нового тестового каталога и A/B выполняются `tools/check_cancelled_stereo.py`:

```sh
python tools/check_cancelled_stereo.py prepare REPO NEW_FIXTURE
python tools/check_cancelled_stereo.py run NEW_FIXTURE/manifest.json BASE_WORKTREE NEW_BEFORE.json
python tools/check_cancelled_stereo.py run NEW_FIXTURE/manifest.json CANDIDATE_WORKTREE NEW_AFTER.json
python work/test_cancelled_stereo.py
```

`python` — локальный `work/asr-env/bin/python`; обоим worktree нужны одинаковые `work/models`. Для ASR использованы `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`, `HF_DATASETS_OFFLINE=1`, `PYTHONDONTWRITEBYTECODE=1`. Аудио не отправлялось наружу.

Граница исправления: только точная противофаза PCM16/16 кГц. Почти противофазный контроль с разницей в один отсчёт всё ещё теряет речь при downmix; это намеренно оставлено в отчёте. Другие форматы, выбор ближнего/неповреждённого канала и реальные стереозаписи требуют отдельной проверки. Ранее созданные нулевые mono-WAV и их готовые кэши автоматически не восстанавливаются.
