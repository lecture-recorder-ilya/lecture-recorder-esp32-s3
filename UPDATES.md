# Обновления Mac и Android

Версия этой сборки: **0.5.0**, код **7**. Версия, код и совместимость окружения находятся в `release.json`.

## Установщик в 0.4.0

Первый запуск выполняется через `lecture-recorder-0.4.0-arm64.dmg`. Нативный мастер включает отдельный Python 3.12.12, устанавливает пакеты из файлов с зафиксированными версиями и хешами, загружает проверенные модели и проверяет их загрузку без сети. Пауза сохраняет загруженные части, восстановление не заменяет библиотеку и настройки телефона. Инструкция: [INSTALL.md](INSTALL.md).

Управляемый проект находится в `~/Library/Application Support/Lecture Recorder/project`, приложение в `~/Applications` ссылается на его bundle. Поэтому обычный пакет обновления заменяет код и приложения по прежним правилам. Установщик использует ту же блокировку, что обновления. Во время записи, очереди обработки или сопряжения он просит дождаться завершения. В меню приложения есть восстановление компонентов и полный выход из сервисов.

## Что обновляется само

- Mac проверяет GitHub Releases при запуске сервиса и раз в 6 часов. Кнопка в «Настройки → Обновления» запускает проверку сразу. Пакет скачивается заранее и устанавливается, когда нет записи, запуска подключения, задач распознавания и активного мастера сопряжения телефона. Сервисы перезапускаются, открытый интерфейс подхватывает новую версию. Изменения нативной оболочки Mac и Bluetooth-помощника начинают работать при следующем запуске этих приложений.
- Android проверяет релиз при открытии приложения и раз в 6 часов, пока оно открыто; во время записи проверка откладывается. APK скачивается автоматически. Установка запускается кнопкой через системный установщик: Android требует разрешение и подтверждение пользователя. После установки уже применённый APK убирается из списка ожидающих обновлений.
- Список записей и открытый текст Mac обновляются автоматически. Изменённая расшифровка загружается повторно, даже если имя записи и статус обработки не изменились.
- При соединении с настроенным телефоном Mac примерно раз в 10 секунд передаёт новые и изменённые расшифровки. На Android они появляются в «Тексты лекций с Mac». Открытый текст обновляется с сохранением положения прокрутки. Он хранится отдельно от аудио и остаётся после подтверждённого переноса WAV. При потере связи повторная отправка происходит после восстановления соединения; без связи текст не синхронизируется. Фоновая работа ограничена жизненным циклом службы Android; при её остановке нужно снова открыть приложение или нажать «Перенести на Mac».

## Сопряжение в 0.3.0

На Mac и Android добавлен мастер подключения: поиск в общей Wi-Fi сети, 12-символьный код Mac и подтверждение одинаковых 6 цифр. Настройки и ключ синхронизации сохраняются автоматически; редактировать файлы и использовать отладку Android не нужно. Обмен настройками защищён TLS с проверкой кода Mac. ESP для сопряжения необязательна; уже настроенный микрофон передаётся телефону вместе с подключением.

Код действует 5 минут. Отмена до подтверждения сохраняет прежнее подключение. На обоих устройствах можно отключить сопряжение с сохранением аудио и текстов. Android собран с `debuggable=false`, служба записи не экспортируется. USB-перенос автоматически выбирает телефон, который принимает подписанный запрос, без ручного серийного номера. Подробности: [PAIRING.md](PAIRING.md).

Новые Python-зависимости не добавлены. Mac использует встроенный `/usr/bin/openssl` для временного сертификата; совместимость окружения остаётся `runtime: 1`.

## Синхронизация и распознавание из 0.2.1

Ошибки отдельных файлов не останавливают перенос остальных записей и текстов. Повторные попытки идут с интервалом от 10 секунд до 5 минут; новая версия файла проверяется сразу. Разрыв соединения запускает попытку через следующий доступный канал. Частично перенесённый WAV продолжается по HTTP Range, а подтверждение удаления по-прежнему требует проверенную копию на диске. USB-серийный номер необязателен для Wi-Fi и Bluetooth.

Режим «Автоматически» выбирает установленную русскую модель с проверкой слов, иначе Whisper. Ручной выбор сохраняется. Для окончательной расшифровки каждый блок читает по 2 секунды соседнего звука с обеих сторон; слова попадают только в своё временное окно. Кэш проверяет SHA-256 исходного WAV, версию распознавания и пользовательские термины, включая источники объединённой записи. Несовместимый или повреждённый кэш архивируется перед новым разбором. Первый разбор после перехода на 0.2.1 выполняется заново; исходные записи и предыдущие расшифровки сохраняются.

Итоговый текст имеет приоритет над черновиком при отправке на телефон. Неразборчивые места отмечаются для проверки по аудио. Эти изменения проверены на синтетических примерах; улучшение точности на настоящей паре требует сравнения с исходным WAV.

## Требования к GitHub Releases

Источник: `lecture-recorder-ilya/lecture-recorder-esp32-s3`. Проверяется последний обычный опубликованный релиз; черновики и предварительные релизы пропускаются. Тег должен совпадать с `v` + `version`, например `v0.4.0`.

Релиз должен содержать:

- `lecture-mac-update.zip`;
- `lecture-recorder.apk`;
- `SHA256SUMS.txt` для ручной проверки.

Клиенты требуют SHA-256 из поля `digest` GitHub API. При отсутствии контрольной суммы установка отклоняется. Mac дополнительно проверяет пути, синтаксис Python, обязательные файлы, увеличение кода версии и совместимость `runtime`. Android проверяет пакет приложения, увеличение `versionCode` и совпадение сертификата подписи с установленным приложением.

**Android сейчас рассчитан на публично доступные Releases.** Токен владельца в APK не встраивается. Mac поддерживает необязательный `LECTURE_GITHUB_TOKEN` в окружении процесса, с правом чтения нужного репозитория. Для приватного репозитория нужен отдельно спроектированный способ авторизации телефона либо публичный источник обновлений с соответствующим изменением `REPO`/`REPOSITORY` в обоих клиентах.

Канал сборки 0.4.1 настроен на `lecture-recorder-ilya/lecture-recorder-esp32-s3`. Репозиторий приватный: без разрешённого доступа GitHub возвращает 404, приложение показывает причину и продолжает обычную работу. Открытый в браузере GitHub-аккаунт сам по себе не авторизует фоновые обновления Mac или Android. Доступные участникам готовые сборки размещаются в [Releases](https://github.com/lecture-recorder-ilya/lecture-recorder-esp32-s3/releases).

## Подготовка следующего релиза владельцем

1. Измени `version` и увеличь `code` в `release.json`. Сохраняй `runtime: 1`, пока новые исходники совместимы с уже установленными Python-окружениями. Изменение зависимостей требует отдельной установки окружения; несовместимый `runtime` автоматический установщик отклонит.
2. Собери Mac: `python3 tools/build_mac.py`.
3. Собери Android: `python3 outputs/android/build.py`. Используй **тот же ключ**, которым подписан установленный APK. Путь задаётся `LECTURE_KEYSTORE`, пароль — переменной окружения `LECTURE_KEY_PASSWORD`; ключ и пароль не публикуются. Указанный, но отсутствующий ключ вызывает ошибку, вместо создания другого.
4. Выполни `python3 tools/build_update_release.py`. Готовые файлы появятся в `work/release`.
5. Опубликуй обычный GitHub Release с соответствующим тегом и тремя файлами из `work/release`.

Для новых установок дополнительно собери DMG командой `python3 tools/build_installer.py` и приложи его к релизу. Перед публичным распространением подпиши приложения Developer ID и выполни notarization Apple: текущий сборочный скрипт использует локальную подпись.

Первый запуск новой установки выполняется через DMG. Разработчик может использовать полную копию проекта после `tools/setup_mac.py` и установки моделей по README. Пакет `lecture-mac-update.zip` предназначен для обновления уже настроенного проекта: Python, модели и персональные настройки в него не входят. Внутри проекта Mac-приложения остаются в `outputs`; установщик создаёт ссылку в папке приложений пользователя.

Локальная Android-сборка подписана новым локальным ключом в `work/android-tools/lectures.keystore`. Этот ключ не включён в ZIP и должен храниться у владельца. Такая сборка **не обновит APK другого автора**, подписанный другим ключом: для него нужен исходный ключ автора. Локальный ключ с паролем по умолчанию предназначен для разработки; для распространения используется собственный защищённый ключ.

## Сохранность данных

В пакет Mac разрешены только код интерфейса/сервисов, библиотеки интерфейса и два bundle приложения. `recordings`, `analysis`, `study`, `lessons`, личное расписание, окружения, модели и токены не заменяются. До копирования создаются резервные копии в `work/updates/backup` и журнал транзакции. Ошибка копирования откатывает файлы; незавершённая транзакция восстанавливается при следующем запуске. Это не проверка работоспособности новой версии после запуска: сохраняй резервную копию проекта перед первым использованием нового канала обновлений.

WAV на Mac получает актуальный заголовок и `fsync` каждые две секунды. При запуске повреждённые стандартные заголовки PCM 16 kHz mono исправляются по фактической длине файла; отсчёты не корректируются. Это помогает после аварийного завершения, но не возвращает звук, который ещё не попал на диск.

## Первое соединение телефона

Открой **Настройки → Телефон и Mac** на Mac и **Подключить Mac** на Android. Мастер сам сохраняет согласованные настройки. Инструкция и восстановление после ошибки: [PAIRING.md](PAIRING.md). Для записи с ESP также нужен настроенный микрофон.

Проверка на настоящем Android и ESP и установка поверх ранее установленного APK ещё нужны. Автоматическая загрузка из приватного релиза на телефоне не поддерживается. Сборка и офлайн-тесты не подтверждают качество микрофона или распознавания на паре.

## Подпись Android 0.4.1

APK версии 0.4.1 подписан сохранённым локальным ключом Ильи. SHA-256 сертификата: `bba052ead71e2742557b333f8797ab34c1b837b0fc3d653a14a886ccbc82a2e9`. Он совместим с предыдущими сборками Ильи, подписанными этим ключом.

APK релиза Макса 0.4.0 имеет другой сертификат (`6485334c883db98cd1ed8972d51636b9508b7a13826788e34251669b3c2455d6`). Обновление поверх него требует исходного ключа Макса; данный APK его не заменит. Не удаляйте приложение с неперенесёнными записями для обхода несовпадения подписей.


## Подпись Android 0.5.0

APK 0.5.0 / код 7 подписан доступным ключом сборки Макса: SHA-256 сертификата `6485334c883db98cd1ed8972d51636b9508b7a13826788e34251669b3c2455d6`. Он обновляет APK с этим же сертификатом, включая сборку Макса 0.4.0. Ключ и пароль не входят в исходники и релиз.

У опубликованного APK Ильи 0.4.1 другой сертификат: `bba052ead71e2742557b333f8797ab34c1b837b0fc3d653a14a886ccbc82a2e9`. Его приватный ключ в текущей среде не найден. Android отклонит установку 0.5.0 поверх этого APK. Публикация и открытие репозитория не устраняют несовпадение подписей. Для обновления без удаления приложения необходимо собрать 0.5.0 прежним ключом Ильи. Удалять приложение с неперенесёнными записями для обхода проверки не следует.
