# Приложения для телефона

| Платформа | Пакет | Совместимость | Состояние |
| --- | --- | --- | --- |
| Android | `lecture-recorder.apk` | Android 8.0+; один APK для разных процессоров | Для обновления используется подпись предыдущего обычного APK |
| iPhone / iPad | `lecture-recorder-ios-project.zip` | Проект для iOS / iPadOS 16+ | Исходники Xcode; подписанного приложения и TestFlight пока нет |
| Mac | `lecture-recorder-0.5.8-arm64.dmg` | Apple Silicon, macOS 14+ | Установщик и закрытый канал обновлений |

Единый APK включает библиотеки для ARM и x86. Локальный разбор доступен в 64-битном процессе. Это не подтверждает работу микрофона на каждой модели: разрешения и ограничения фоновой работы зависят от устройства.

## Android: запись без ESP

1. На экране записи выбери **Микрофон телефона**.
2. Нажми **Начать запись** и разреши микрофон.
3. Заверши запись. WAV останется на телефоне; Mac и интернет для записи не нужны.
4. Открой **Аудио** и выбери запись для расшифровки и конспекта.

После начала записи экран можно погасить или заблокировать при любом источнике звука. Android продолжает запись через фоновую службу с уведомлением и кнопкой «Остановить и сохранить».

При первой установке выбран микрофон телефона. Существующий выбор ESP после обновления сохраняется. Android подключает ESP по Bluetooth. Запись работает через foreground service с уведомлением и кнопкой остановки. Если микрофон не поддерживает 16 кГц, приложение пробует 48 и 44,1 кГц и пересчитывает звук. На диск сохраняется PCM16 mono 16 кГц.

Готовое аудио можно импортировать на вкладке «Аудио». Текст с таймкодами и сомнительными местами появляется после локального разбора.

## Локальный разбор Android

На вкладке **Аудио** выбери запись и нажми **Разобрать**. В отдельном экране фразы появляются карточками с интервалами по мере распознавания. Перемотка по дорожке подсвечивает подходящую карточку, а нажатие на её таймкод включает звук с этого места. После сохранения текста нажми на слово в карточке, чтобы исправить его вручную. Правку можно отменить кнопкой «Вернуть исходное».

Конспект появляется автоматически в соседней панели после распознавания. Готовый разбор открывается той же кнопкой, а повторное распознавание запускается из самого экрана. **Импорт** добавляет аудио. Список включает лекции, для которых сохранён только текст.

На экране **Запись** раскрой верхнюю строку состояния и нажми плитку **Добавить устройство**. Для нового сопряжения нужна прошивка ESP 1.2.0. На включённой плате удерживай BOOT около секунды, затем нажми **Добавить устройство**. Если Android покажет запрос Bluetooth, подтверди его. Ввод кода не требуется. После сопряжения появится вращаемая модель корпуса ClipMic. Уровень заряда отображается, если устройство передаёт его в ответе ESP или через Bluetooth Battery Service. В настройках можно проверить версию прошивки.

- Первый локальный разбор обычно загружает около 570 МБ моделей. Если модель конспекта уже на телефоне, загрузка модели речи займёт около 225 МБ. После загрузки распознавание, таймкоды и конспект работают локально. Нужен 64-битный Android.
- Во время разбора можно свернуть приложение. Прогресс и отмена доступны на вкладке «Аудио» и в уведомлении при разрешённых уведомлениях.
- Текст сохраняется перед составлением конспекта. Если конспект прервался, нажми **Завершить конспект**. Ранее сохранённые расшифровки и конспекты остаются в библиотеке после обновления.
- Распознавание выполняет [GigaAM v3](https://github.com/salute-developers/GigaAM) с [ONNX Runtime](https://onnxruntime.ai/). При сбое используется [Vosk](https://alphacephei.com/vosk/models). Ключевые фразы выбирает [Qwen3](https://huggingface.co/litert-community/Qwen3-0.6B). Конспект составляется из фраз расшифровки. Сомнительные места можно прослушать по таймкодам.

Для отдельной сборки на Mac выполни `python3 outputs/android/build.py --preview` с Android SDK 36, Build Tools и JDK 21 или новее. Сборка ставится рядом с версией из релиза и хранит собственные записи. Обе сборки используют версию `android.version` из `release.json`. У отдельной сборки свой код `android_preview.code`, пакет и подпись для обновления уже установленных экземпляров. Пакет для неё прикладывается к релизу при наличии прежнего ключа подписи. Обычный APK теперь тоже поддерживает локальный разбор.

## iPhone и iPad

Подготовлен отдельный нативный клиент: запись, импорт аудио и видео, библиотека, получение конспекта и текста, прослушивание по нажатию на фразу. Перенос по Wi-Fi использует протокол Mac: подтверждение кода, HMAC, SHA-256, продолжение скачивания и подтверждение сохранения.

Открой [проект iOS](outputs/ios/README.md) в Xcode. Владелец пока не подключил Apple Developer: подписанного IPA, публичной установки и автообновлений iPhone в 0.5.8 нет. TestFlight / App Store — следующий шаг. Архив проекта не устанавливается на телефон как приложение.

## Обновления

- Mac сам находит новую версию в приватном GitHub после однократного входа.
- Начиная с Android 0.5.9 открой **Настройки → Обновления → Войти в GitHub**. Подтверди код в браузере аккаунтом с доступом к репозиторию. Следующие проверки и загрузка идут напрямую с GitHub. Установку подтверждает Android после завершения записи и разбора.
- Для iPhone версии будут приходить через канал Apple после его настройки.

## Испытания

Проверяются сборка APK, подпись, очистка, импорт, закрытый канал и проверка APK. Ядро iOS проверяется реальными HTTP-запросами клиента Mac: список WAV, SHA-256, Range, защита от повторов, сохранение текстов и подтверждение переноса с сохранением аудиокопии. Сборка с iOS SDK выполняется отдельным workflow GitHub Actions.

ИИ-сборка проверялась на Samsung с ARM64. Тесты протокола и сборки дополняют проверку на устройстве. Для iPhone требуется отдельная проверка подписанного приложения.

## Расписание МИРЭА

При первом открытии Android и Mac один раз предлагают указать группу и курс. Профиль можно изменить в настройках. Расписание загружается с [сайта МИРЭА](https://schedule-of.mirea.ru/) по коду группы. После загрузки используется локальный кэш.

После остановки записи приложение предлагает пару на время начала записи по Москве. При неоднозначном совпадении выбор остаётся за пользователем. Можно выбрать другой предмет, вписать свой, сохранить без пары или удалить запись после подтверждения. Если приложение закрыть, незавершённый выбор остаётся. На Android запись попадает в очередь переноса после сохранения, выбранный предмет переносится вместе с ней.
